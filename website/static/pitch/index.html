The problem

The Internet's protocols are specified in prose.

9,854
RFC entries in the RFC Editor index, read 4 November 2026
  • Requirements are sentences: RFC 6455 alone has 140 occurrences of MUST.
  • Every implementation re-reads the text and re-derives the state machine by hand.
  • Grammars, bit layouts and registries are scattered across sections, comments and IANA pages.
  • Conformance is per project: a test suite here, an interop run there, no shared matrix of which sentence is met.
  • Nothing links a line of code back to the sentence it implements.
RFCspec2 · problem

The ambition

From any RFC to a checkable implementation.

rfc-editor.org→ cited catalogue→ ESS model→ generated core+ conformance suite

Catalogue

Requirements, grammars, bit layouts, registries, defined procedures and limits. Each item carries its source span and a digest.

Specification

State machines as ess-protospec/1, types and registries as ESS. Bytes and bits in a wire sidecar, rfcspec-wire/1.

Outputs

A sans-IO Rust core per protocol, generated test vectors, traces, and a requirement matrix per implementation.

A standard library of protocols that cites the RFCs it implements, sentence by sentence.

RFCspec4 · pipeline

Determinism and AI

AI proposes. Checks and reviewers decide.

  • AI runs in one stage, S3, where prose has to become structure.
  • Every proposal quotes the span it relies on. A quote that does not occur verbatim in the locked source is refused before a human sees it.
  • Proposals are typed documents with the model id and the digest of the prompt and inputs. They are recorded and replayed, so CI runs offline.
  • A proposal changes nothing until a review decision is written to the overlay.
  • No gate calls a model.

Worked example

WebSocket: one profile, six RFCs.

6455 base · 7936 registry · 8307 well-known URIs · 8441 over HTTP/2 · 9220 over HTTP/3 · 7692 permessage-deflate (optional)

  • 6455 has no XML: it tests the plain-text path. 9220 tests the XML path.
  • §5.1: “a client MUST mask all frames”, “A server MUST NOT mask any frames”.
  • Six IANA registries, including opcodes and close codes.
  • Independent oracle: Autobahn|Testsuite, “over 500 test cases”.

Lowering into ESS pays off

The first exploration found a gap.

A model of the closing handshake, checked with ess protocol explore. The first draft let the client drop the connection after the close timeout, as RFC 6455 §7.1.7 says.

draft: client close on timeout

"verdict": "inconclusive",
"reason": "dead end with outstanding
  queue, timer or flush obligations",
"explored_states": 9,
"explored_transitions": 10

The server's close frame is still queued to a client that can no longer receive it.

model in the design

"verdict": "passed",
"reason": "bounded model search completed
  for the supplied finite input witnesses",
"explored_states": 10,
"explored_transitions": 11

On TCP the frame is discarded with the connection. The model format cannot say that yet: gap G9.

Where ESS grows

Each gap is raised when an RFC needs it.

G2modular, bounded arithmeticTCP sequence numbers, NTP timestamps
G3byte-string fields with length boundsmasking key, close reason, payloads
G4dynamic participants keyed by idHTTP/2 and QUIC streams, DNS queries
G5layering one protocol over another's streamWebSocket over HTTP/2 and HTTP/3

G7timers from field valuesNTP poll interval, TCP retransmission
G8wire layerevery wire protocol and data format
G9close discards in-flight transmissionsWebSocket §7.1.7, every teardown

Until a gap closes, the requirement shows as unsupported: ess-gap Gn. Nothing is lowered that silently loses a rule.

RFCspec10 · ESS gaps

Native and Spindle

One generated core, two ways to run it.

Wire codec

Incremental, bounded parsers and printers. Native Rust, or a WASM module that Spindle calls with call_pure: pure, fuel-limited, deterministic.

Protocol machine

A sans-IO step(state, event) from the protospec model. Native today; on Spindle once it executes protocol models.

Application

Runs on Spindle and names an exchange (session, request-response), never a protocol. The environment binds it to a generated port.

Reliability without trusting the generator:

  • parse and print round trips, plus generated vectors from grammars and layouts
  • trace replay against the model, and bounded exploration of the model
  • fuzzing at the limits, and an independent external suite

What success looks like

“Implementation X conforms to profile P” is a claim a machine can check.

rfc6455  WebSocket, profile websocket, client+server
R5.1-3  5.1  MUST      satisfied   wire::Frame   pass
R5.1-4  5.1  MUST NOT  satisfied   wire::Frame   pass
R7.4-2  7.4  MUST      unsupported ess-gap G1    gap
R5.5-1  5.5  SHOULD    satisfied   (not run)     inconclusive
...
claim: no  (1 gap, 0 failures, 1 inconclusive)

Illustrative rows; ids are assigned by the importer.

VerdictWhen
passsatisfied and a linked test passed
faila linked test failed
gapMUST-level unsupported
deviationSHOULD-level unsupported
inconclusiveno passing test, or a skip
n/anot applicable, or out of scope

The claim holds when no MUST-level row in scope is fail, gap or inconclusive.
