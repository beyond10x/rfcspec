## Story

`rfcspec-docs generate` renders the committed bulk summary as the site's RFC index: an overview page
and one table page per thousand RFC numbers, never one page per RFC. Each row shows the metadata and
the requirement counts by level; an RFC that a reviewed profile includes is marked and linked to its
profile page; the protocol catalogue index links the RFC index. Generation stays offline: it reads
only `bulk/rfc-summary.jsonl` and `profiles/`.

## Acceptance

`task check` exits 0 offline, `task website` builds, and the built site serves
`/rfcspec/docs/catalog/rfcs/` and eleven range pages whose rows together are exactly the rows of
`bulk/rfc-summary.jsonl`, with RFC 6455 linked to `/docs/catalog/websocket`, RFC 1035 to
`/docs/catalog/dns` and RFC 868 to `/docs/catalog/time`.

- Pages: `website/docs/catalog/rfcs/index.md` and `website/docs/catalog/rfcs/<NNNNN>.md` for each
  thousand that has a row, named by its first number padded to five digits (`00000` for RFC 1 to
  999, …, `10000` for 10000 to 10999; the 4 November 2026 index reaches RFC 10080, so eleven
  pages). A range without a row gets no page.
- A range page is one table, ascending by number: RFC (linked to
  `https://www.rfc-editor.org/rfc/rfc<N>`), title, status, stream, area (`-` when none), date,
  obsoleted by, updated by (RFC numbers, each linked to its row's range page), requirements by level
  (`4 MUST, 2 SHOULD` style through the existing `by_level` ordering; `none` for `{}`), and profile
  (the name of each profile whose `rfcspec.lock` holds the RFC, linked to its page; empty
  otherwise).
- The overview states the index SHA-256 and extractor version from the header, the row count, how
  many rows have at least one requirement, the total per level, the reviewed profiles with their
  RFCs, and one link per range page with its row count. A unit test renders both from the
  `story:bulk-summary-format` fixture summary and asserts the RFC 6455 row cells and the overview
  totals.
- `website/docs/catalog/index.md` (the protocol catalogue) gains one line linking the RFC index; its
  table is unchanged. `website/sidebars.ts` needs no edit (the category is autogenerated from
  `catalog/`); if the 11 pages crowd it, the range pages are hidden from the sidebar via front
  matter and reached from the overview.
- `rfcspec-docs generate --check` exits non-zero naming the file when a range page or the overview is
  missing, stale, hand-edited or unexpected (`unexpected website/docs/catalog/rfcs/<file>`); a unit
  test covers each. Every page passes `passive_check` (titles holding `<`, `{` or `|` stay passive
  through `page::cell`; the test includes such a title).
- `rfcspec-docs provenance` on the built site lists `/rfcspec/docs/catalog/rfcs/` and each range
  route in `.well-known/b10x-routes.json`. The generated pages total under 4 MiB.

## Domain relations

- Summary row -> Rfc, one-to-one, a projection: `ess/domains/catalogue.yaml`, view
  `rfcspec.catalogue.Rfcs`, `source: rfcspec.catalogue.Rfc`. A page owns nothing.
- Profile -> Rfc, one-to-many, referencing: inferable (inferred from `ess/domains/profile.yaml`, type
  `rfcspec.profile.ProfileRfc`, field `rfc`, no `relations:` entry). The profile column is read from
  each profile's lock, as the stage S0 test of `story:catalog-index` reads it.
- Rfc -> Rfc update edges, zero or many: inferable (inferred from `ess/domains/catalogue.yaml`, entity
  `rfcspec.catalogue.Rfc`, fields `obsoleted_by` and `updated_by`, `List<Integer>`, no `relations:`
  entry); a number without a row is shown unlinked.

## Scope

`crates/rfcspec-docs` (a new `src/bulk.rs`, outputs registered in `src/main.rs`, tests),
`website/docs/catalog/rfcs/` (generated), `website/docs/catalog/index.md` (regenerated),
`Cargo.lock` if `rfcspec-docs` gains a dependency.

Depends on `story:bulk-fetch-corpus`: the pages render its committed `bulk/rfc-summary.jsonl`, and
the row types come from `story:bulk-summary-format`. Shares `crates/rfcspec-docs/src/catalog.rs`
callers and `website/docs/catalog/index.md` with `story:websocket-review-matrix`, which lands first
through that chain.
